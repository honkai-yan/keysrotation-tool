# 密钥轮换

基于 [egui](https://github.com/emilk/egui) 的桌面小工具，用来维护一份加密的密钥库。

- 密钥库是 WebDAV 服务器上的单个 SQLite 文件 `ptoolkit_keys.db`。
- 每条密钥内容都经过对称加密后再保存。
- 软件运行时数据库只存在于内存中，不落盘，退出即丢失。
- 窗口在前台时每 2 秒自动检查服务器上的数据库，有新版本就同步过来。

## 功能

- **WebDAV 同步**：启动时下载数据库到内存，每次修改后整库上传；先写 `ptoolkit_keys.db.tmp`，再用 WebDAV MOVE 原子替换主库，避免上传中断把服务器上的库写坏。
- **自动同步**：窗口在前台时每 2 秒下载一次数据库并比较 SHA-256 摘要。服务器版本变化时直接采用服务器版本，并在状态栏右侧提示“数据库自动同步成功”。
- **内容加密**：每条内容使用 AES-256-GCM 加密，密钥由对称加密密钥经 Argon2id 派生。
- **按需解密**：内容默认显示为 `*`，点击后解密，1 分钟后自动重新遮蔽。
- **编辑**：双击描述或明文内容进入编辑，Enter 保存，Esc 取消。支持新增和删除条目；删除前有二次确认。
- **复制**：右键明文内容复制到剪贴板，状态栏闪烁提示“复制成功”。
- **自动登录**：保存 token 与账号密码，启动时优先用 token 自动登录。
- **修改对称加密密钥**：用新密钥重新加密全部条目，上传成功后本地才切换到新密钥。
- **上传失败恢复**：上传失败时显示遮罩并等待自动同步从服务器恢复；恢复失败则回到配置向导。
- **损坏库修复**：只有启动时（首次下载）发现服务器数据库缺失或损坏才会新建空库；运行期间内存中已有库时，同步发现服务器库缺失或损坏，会直接用内存中的库覆盖修复，不新建空库。
- **退出登录**：主页右上角按钮，清空账号、密码、token 和对称密钥，只保留服务器地址。

## 环境要求

- Rust 1.85 或更新版本（项目使用 edition 2024）。
- Windows 或 macOS。
- C 编译器。`rusqlite` 的 `bundled` 特性会编译内置的 SQLite；Windows 上安装 MSVC 生成工具即可，macOS 上执行 `xcode-select --install`。
- 服务端：OpenList，并开启 WebDAV。使用的账号需要 WebDAV 的读取和管理（写入）权限，否则会返回 403。
- 中文字体已内置在程序中（Noto Sans SC 的 GB2312 子集，SIL OFL 1.1），不依赖系统字体。

## 构建与运行

```bash
cargo build --release
./target/release/rust_keyrotation
```

开发时可以直接 `cargo run`。程序构建为普通二进制，不打包成 `.app`。macOS 下关闭窗口即退出程序。

Windows 下 Release 构建使用 GUI 子系统，不会弹出控制台窗口，只保留应用窗口；Debug 构建保留控制台，方便查看运行输出。

运行测试：

```bash
cargo test
```

## 使用说明

### 1. 配置向导

首次启动，或本地没有保存服务器地址和对称加密密钥时，进入向导页面：

- **服务器地址**：填写完整的 WebDAV 地址，例如 `http://192.168.1.10:5244/dav/`。协议可以是 `http` 或 `https`。
- **对称加密密钥**：输入框中显示为圆点。
- 点击“确认”后连接服务器。

### 2. 登录

连接时程序先检测服务器是否需要账号密码：

- **不需要**：直接下载数据库，进入主页。
- **需要**：若本地保存的 token 仍然有效，则自动登录；否则显示登录页，输入账号和密码后登录。登录成功后保存 token、账号和密码。

这一阶段的首次下载如果发现服务器上不存在数据库文件（404）或文件已损坏，才会新建一个空库。下载数据库时遇到网络或其他 HTTP 错误，会重置登录状态（清空对称密钥、账号、密码和 token）并回到向导页；仅连接检测或登录请求本身失败时显示“连接失败”页，可以重试或修改配置。

### 3. 主页

顶部是服务器地址和端口，两者双向同步。修改地址或端口后失焦或按回车即生效。右侧是“对称加密密钥”输入框，输入新密钥后按回车即可修改。

下方表格有“描述”和“内容”两列，鼠标悬停的行会高亮。

| 操作 | 效果 |
|---|---|
| 点击 `*` | 解密并显示明文，60 秒后重新遮蔽 |
| 双击描述或明文内容 | 进入编辑，Enter 保存，Esc 取消 |
| 右键明文内容 | 复制到剪贴板，状态栏闪烁“复制成功” |
| 右键描述 | 删除该条目；会先弹出“确定删除该密钥吗？”确认框 |
| 点击“新增” | 新增空条目，并直接进入描述编辑 |
| 点击“退出登录” | 清空账号、密码、token 和对称密钥，回到向导页 |

补充说明：

- 只有解密后的内容才能编辑和复制。
- 正在编辑的条目禁用业务右键（删除/复制）；输入框自身的编辑操作不受影响。
- 编辑明文内容期间，倒计时暂停。确认后重新开始 60 秒计时，取消则继续原来的倒计时。
- 每次修改都会写入内存数据库、整库上传到服务器，上传期间界面会显示加载遮罩。
- 修改对称加密密钥时，会先用旧密钥解密全部条目，在内存中构造新库并上传，上传成功后本地才切换到新密钥；失败则保持原状并进入恢复流程。

### 4. 自动同步

窗口在前台且处在主页时，每 2 秒下载一次服务器上的数据库并比较 SHA-256 摘要：

- 摘要相同：不做任何提示。
- 摘要不同：直接采用服务器版本（整库覆盖，不合并），期间短暂显示加载遮罩，状态栏右侧提示“数据库自动同步成功”。
- 采用服务器版本等同于重连一次：所有已解密的密钥重新遮蔽，正在编辑的输入框会被重置，未完成的删除确认也会关闭。
- 如果本地刚提交了修改，则以本地上传为准（后上传覆盖服务器版本）。
- 服务器上的数据库不存在或损坏时，把内存中现有的库上传上去修复，状态栏提示“服务器数据库不存在/损坏，已用本地数据库修复”。

只有主页且窗口有焦点时才会自动同步；上传失败后的恢复同步例外，它会在 200ms 后主动发起。

**空库只会在启动时创建**：启动、登录或修改地址后的首次下载，遇到 404 或文件损坏才会新建空库。此后只要内存里已经有一份库，运行期间的任何同步（自动同步轮询、上传失败后的恢复同步）发现服务器库缺失或损坏，都不会新建空库，而是把内存中的库上传覆盖上去修复。

### 5. 同步失败与恢复

- **上传失败**：显示红色叉号遮罩“上传失败，请等待自动同步恢复”，期间禁止操作；200ms 后发起一次恢复同步。
  - 服务器库可正常读取：采用服务器版本，界面恢复。
  - 服务器库缺失或损坏：用内存中的库上传修复，界面恢复，状态栏提示“服务器数据库不存在/损坏，已用本地数据库修复”。
  - 服务器库能解析但密钥都对不上，或恢复同步本身网络失败：回到配置向导，状态栏提示“数据库上传失败且恢复失败”。
- **普通自动同步失败**：回到配置向导，状态栏提示“自动同步失败”。
- **修改地址后**：如果地址确实变化，回到登录页并清空账号、密码和 token（保留对称密钥）。新服务器需要登录时等待手动登录，不需要登录时直接下载数据库。
- 以上失败重置都只保留服务器地址和端口，对称密钥、账号、密码和 token 会被清空。

### 6. 状态栏

- 状态栏固定在窗口最底部。
- 左侧显示操作结果（如“复制成功”“同步完成”“已退出登录”及各类失败原因），右侧显示自动同步提示。
- 所有提示在闪烁动画结束后仍然保留，直到被下一条提示覆盖。

## 数据存放与安全

| 位置 | 内容 | 保护方式 |
|---|---|---|
| 服务器 WebDAV 目录下的 `ptoolkit_keys.db` | 整个 SQLite 数据库 | 每条内容使用 AES-256-GCM 加密 |
| 本地 `~/.rust-keyrotation/config.json` | 服务器地址、对称加密密钥、账号、密码、token | 明文保存。Unix 下目录权限 700，文件权限 600 |
| 内存 | 解密后的数据库和明文内容 | 退出即丢失。明文 60 秒后从内存中移除 |

加密方式：

- 对称加密密钥经 Argon2id 与随机 16 字节盐派生出 256 位密钥。盐保存在数据库的 `meta` 表中。
- 每条内容使用 AES-256-GCM 加密，随机 96 位 nonce，存储格式为 `base64(nonce || 密文)`。
- 数据库中保存了一条用派生密钥加密的校验值。密钥不正确时会提示“加密密钥与服务器数据库不匹配”，并回到向导页，不会解出乱码，也不会覆盖服务器上的库。

> **注意**
>
> - **对称加密密钥丢失后，服务器上的密文无法恢复**，请妥善保管。
> - 本地配置中的对称加密密钥和 WebDAV 密码是明文，依赖文件权限保护。不要把 `~/.rust-keyrotation` 复制到不安全的位置。
> - 同步是整库覆盖，不做多设备合并。两台设备同时修改时以后上传的一方为准；其他设备的下一次自动同步会直接采用服务器版本。

## 项目结构

```
assets/
├── NotoSansSC-GB2312.otf   内置中文字体（GB2312 子集，SIL OFL 1.1）
└── NotoSansSC-OFL.txt      字体许可证
src/
├── main.rs     程序入口与窗口设置
├── app.rs      界面与业务逻辑：向导、登录、主页、自动同步、遮罩、状态栏
├── config.rs   ~/.rust-keyrotation/config.json 的读写
├── crypto.rs   Argon2id 密钥派生与 AES-256-GCM 加解密
├── db.rs       内存中的 SQLite 数据库
├── sync.rs     单线程同步 worker：连接、登录、下载、上传串行执行
└── webdav.rs   WebDAV 访问、原子上传与 OpenList 登录接口
```

需求与设计决策记录在 `AGENTS.md` 中。

## 开发说明

- `.env` 中的 `TEST_SERVER`、`TEST_ACCOUNT`、`TEST_PASSWORD` 是测试服务器信息。程序不读取该文件，`.gitignore` 已将其排除，请勿提交。
- `TEST_SERVER` 只是服务器根地址，使用时需要拼接 `/dav/`。
- 数据库同步（下载、上传、自动同步）全部经由 `sync.rs` 中的单个后台 worker 串行执行，任何时刻最多只有一个同步连接。
- `cargo test` 覆盖数据库序列化、密钥校验、损坏库识别、摘要比较与自动同步决策等纯逻辑。
- HTTP 客户端使用 `reqwest`（阻塞模式）。`ureq` 3.x 的 HTTP/1.1 实现会拒绝 PROPFIND 方法，因此没有使用它。

## 已知限制

- 内置字体只覆盖 GB2312 与常用标点，生僻字可能显示为方框。
- 没有多设备合并逻辑：服务器数据库始终是唯一权威版本，多设备同时修改时以后上传者为准。
- 服务器数据库损坏时不会尝试从损坏文件里恢复数据：启动阶段会用新建的空库覆盖，运行阶段会用内存中现有的库覆盖修复。
